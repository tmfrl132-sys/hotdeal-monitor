# 딜 모니터 설계서

- 작성일: 2026-11-13
- 상태: 승인됨 (2026-11-14)

## 1. 목적

사용자는 상테크, 알뜰폰 요금제(특히 "쌀먹"), 신용카드 혜택, 재테크 이벤트, 핫딜 정보를 커뮤니티에서 직접 찾아 왔다. 좋은 글은 몇 분 만에 품절되기도 하고, 반대로 글이 너무 많아서 다 훑기 어렵다. 이 프로그램은 공개 커뮤니티를 자동으로 살피고 "혹할 만한" 글만 골라 텔레그램으로 링크를 보낸다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 5개 카테고리를 감시한다: 재테크, 알뜰폰, 신용카드, 핫딜, 상품권.
- 시간이 급한 글(상품권, 쌀먹, 사용자 키워드)은 2분 안에 알린다.
- 나머지는 반응(추천·댓글)이 기준을 넘는 글만 알린다.
- 사용자가 텔레그램 명령으로 즉시알림 키워드와 제외 키워드를 관리한다.
- 먼저 사용자 PC(Windows)에서 테스트한다. 그 뒤 코드를 바꾸지 않고 Oracle Cloud 무료 서버(Linux)로 옮긴다.

**비목표**
- 네이버 카페 등 로그인이 필요한 곳은 수집하지 않는다. 계정 정지 위험과 약관 문제가 있다.
- 웹 화면, 앱, 지난 글 검색 화면은 만들지 않는다.
- AI 판정은 이번 범위에서 뺀다. 규칙만으로 부족하면 나중에 붙인다.
- 여러 사용자를 지원하지 않는다. 사용자는 1명이다.

**실패 조건 (동작해도 실패로 본다)**
- 알림이 너무 많아서 사용자가 알림을 끄게 된다. 기준선은 즉시알림을 뺀 알림이 하루 30건을 넘는 경우다.
- 같은 글을 두 번 이상 보낸다.
- 사이트에 과한 요청을 보내 IP가 차단된다.
- 다른 사람이 봇 명령으로 설정을 바꿀 수 있다.

## 3. 제약

- **뽐뿌:** 글 목록 HTML은 403으로 막혀 있다. RSS(`https://www.ppomppu.co.kr/rss.php?id=<게시판>`)는 열려 있다. RSS 항목의 `<hits> [a|b|c|d]` 필드에 반응 수가 들어 있다. 순서는 댓글|조회|추천|비추천으로 보이며, 구현 첫 단계에서 실제 글과 대조해 확정한다. 2026-11-13에 확인한 게시판 ID는 다음과 같다.
  - `ppomppu`: 뽐뿌게시판(핫딜)
  - `pmarket`: 쇼핑뽐뿌
  - `money`: 재테크포럼
  - `phone`: 휴대폰포럼(알뜰폰)
  - `coupon`: 쿠폰게시판(페이·상품권 쿠폰)
  - `event`: 이벤트게시판
  - `stock`: 증권포럼
- **클리앙:** `https://www.clien.net/service/board/jirum`(알뜰구매) HTML 목록은 200이다. RSS는 없다.
- **FM코리아:** `https://www.fmkorea.com/hotdeal` HTML은 200이다. 봇 차단(JS 챌린지)이 생길 수 있으므로, 실패하면 해당 소스를 끄고 알린다.
- **신용카드는 유튜브 "정가거부" 채널 기준이다 (사용자 결정, 2026-11-14).** 채널은 `@정가거부`이고 RSS는 `https://www.youtube.com/feeds/videos.xml?channel_id=UC1KHW0JH7zToxC2H69axgzw`다. 로그인 없이 읽힌다. 이 채널은 카드 추천 영상을 한 달에 한 번쯤 올리고, 카드 단종 소식도 다룬다. 다른 할인 정보 영상도 자주 올린다(이틀에 4개 정도). 커뮤니티 카드 글의 반응 기반 감시는 하지 않는다. 채널 커뮤니티 탭 글은 RSS에 나오지 않으므로 잡지 않는다.
- **요청량:** 사이트당 요청 간격은 최소 2초로 한다. User-Agent는 일반 브라우저 문자열을 쓴다. 403이나 429를 받으면 해당 소스를 30분 쉰다.
- **비밀 정보:** 텔레그램 봇 토큰과 사용자 chat_id는 `.env`에만 둔다. 저장소에는 커밋하지 않는다.
- **실행 환경:** Python 3.11 이상. Windows와 Linux 양쪽에서 같은 코드로 돌아야 한다.

## 4. 접근 방식

| 방식 | 장점 | 단점 | 결정 |
| --- | --- | --- | --- |
| A. Oracle Cloud 무료 서버에서 상주 실행 | 24시간 동작, 무료 | 가입 시 카드 인증, 서버 자리 부족 오류 가능 | **최종 운영 환경** |
| B. 사용자 PC에서 상주 실행 | 바로 시작 가능 | PC가 꺼지면 멈춤 | **테스트 환경** |
| C. GitHub Actions 예약 실행 | 서버 불필요 | 실제 간격 10~25분, 봇 명령을 실시간으로 못 받음 | 제외 |

사용자는 B에서 테스트하고 A로 옮기는 방식을 골랐다.

## 5. 구조

Python 프로세스 하나가 비동기로 두 일을 함께 한다.

1. **수집 루프:** 소스별 주기마다 새 글을 가져오고, 걸러서 알린다.
2. **봇 루프:** 텔레그램 `getUpdates` 롱폴링으로 명령을 받는다. 서버에 공개 포트를 열지 않는다.

```
[소스: 뽐뿌 RSS / 클리앙 HTML / FM코리아 HTML]
        │ 2분 또는 10분 주기
        ▼
   수집기(fetch + parse) → 글 목록(Post)
        ▼
   분류기: 카테고리 지정 (게시판 + 키워드)
        ▼
   필터: 제외 → 즉시알림 → 반응 기준
        ▼
   SQLite: 본 글, 보낸 글, 반응 이력, 키워드
        ▼
   텔레그램 발송 (즉시 또는 요약 묶음)
```

**제안 폴더 구조 (빌더 재량)**
```
deal-monitor/
  monitor/
    main.py          # 진입점: 수집 루프 + 봇 루프
    config.py        # settings.yaml 읽기
    sources/         # ppomppu.py, clien.py, fmkorea.py — 소스마다 fetch/parse
    classify.py      # 카테고리 지정
    rules.py         # 제외/즉시/반응 판정
    store.py         # SQLite
    telegram.py      # 발송 + 명령 처리
  settings.yaml      # 소스, 주기, 기준 숫자, 기본 키워드
  .env.example
  tests/             # 파서는 저장해 둔 HTML/RSS 샘플로 테스트
  deploy/            # Oracle용 systemd 서비스 파일, 설치 안내
```

## 6. 동작 상세

### 6.1 소스와 주기 (settings.yaml 기본값)

| 소스 | 주기 | 기본 카테고리 |
| --- | --- | --- |
| 뽐뿌 `coupon` | 2분 | 상품권 / 재테크 |
| 뽐뿌 `phone` | 2분 | 알뜰폰 |
| 뽐뿌 `ppomppu` | 2분 | 핫딜 (상품권 키워드면 상품권) |
| 뽐뿌 `money` | 10분 | 재테크 |
| 뽐뿌 `event` | 10분 | 재테크 |
| 뽐뿌 `stock` | 10분 | 재테크 |
| 뽐뿌 `pmarket` | 10분 | 핫딜 |
| 클리앙 `jirum` | 10분 | 핫딜 / 상품권 |
| FM코리아 `hotdeal` | 10분 | 핫딜 / 상품권 |
| 유튜브 정가거부 RSS | 30분 | 신용카드 / 핫딜 (6.6 참고) |

`ppomppu`를 2분으로 둔 이유는 상품권 대란 글이 주로 뽐뿌게시판에 올라오기 때문이다(빌더 판단).

### 6.2 카테고리 지정

게시판의 기본 카테고리에 제목 키워드 규칙을 덧붙여 정한다. 키워드 사전은 settings.yaml에 둔다.
- 상품권: 상품권, 컬쳐랜드, 해피머니, 문화상품권, 신세계, 롯데, 현대, 온누리, 지류, 모바일상품권, 북앤라이프 …
- 알뜰폰: 요금제, 알뜰폰, 유심, 데이터, 쌀먹, 0원 …
- 카드 단종(커뮤니티 즉시알림용): 단종 키워드(단종, 발급중단, 발급 중단, 막차)와 카드 키워드(카드, 신용카드, 체크카드)가 함께 있는 글

글 하나에 카테고리가 여러 개 걸리면 우선순위 상품권 > 알뜰폰 > 재테크 > 핫딜로 하나만 고른다. 커뮤니티 글 중 카드 단종 조건에 맞는 글은 신용카드 카테고리로 지정한다.

### 6.3 거르기 (순서대로 판정)

1. **제외:** 사이트의 종료/품절 표시가 있거나, 제목에 제외 키워드가 있으면 버린다. 질문글, 후기글 말머리도 버린다. 기본 제외 키워드는 종료, 품절, 마감, 질문, 후기다.
2. **즉시알림:** 다음 중 하나에 맞으면 바로 보낸다.
   - 제목에 즉시알림 키워드가 있다. 기본값은 "쌀먹"이고 사용자가 추가한다.
   - 상품권 카테고리이고, 제목에서 읽은 할인율이 기준 이상이다. 기본 기준은 5%다.
   - 제목이 카드 단종 조건(6.2)에 맞는다. 이 경우 🔥를 붙인다.
3. **반응 기준:** 나머지 글은 올라온 뒤 일정 시간 안에 반응이 기준을 넘으면 보낸다. 카테고리별 기본값은 다음과 같다.
   - 핫딜: 30분 안에 추천 5 이상, 또는 댓글 20 이상
   - 재테크, 알뜰폰: 60분 안에 추천 3 이상, 또는 댓글 15 이상
   - 상품권(할인율 미달): 30분 안에 추천 3 이상
   - 기준 시간이 지나도 넘지 못한 글은 6시간까지 계속 지켜보다가 버린다. 늦게 뜨는 글도 잡기 위해서다.
4. 이미 보낸 글(소스+글번호)은 다시 보내지 않는다.

반응 수는 매 수집 때 갱신한다. 뽐뿌는 RSS `hits`를, 클리앙과 FM코리아는 목록 HTML의 추천·댓글 수를 쓴다. 할인율은 제목의 `n%`, `n.n%` 패턴에서 읽고, 없으면 빈 값으로 둔다.

모든 기준 숫자는 settings.yaml에 둔다. 처음 수치는 추정치이며 PC 테스트 기간에 조정한다.

### 6.4 알림 형식과 시점

- **즉시알림:** 글마다 바로 보낸다. "쌀먹" 글에는 맨 앞에 🔥를 붙인다.
  ```
  🔥 [알뜰폰] ○○모바일 월 0원 요금제 쌀먹 가능 (7개월)
  뽐뿌 휴대폰포럼 · 3분 전 · 추천 2 · 댓글 11
  https://www.ppomppu.co.kr/zboard/view.php?id=phone&no=...
  ```
- **반응 기준 통과 글:** 바로 보내지 않고 모아서 하루 3번(08:00, 12:30, 19:00 KST) 카테고리별 묶음으로 보낸다. 묶음에 글이 없으면 보내지 않는다.
- 텔레그램 링크 미리보기는 끈다. 묶음 메시지가 길어지기 때문이다.
- 발송 실패는 재시도한다. 이 메시지가 텔레그램 4096자 제한을 넘으면 나눠 보낸다.

### 6.5 텔레그램 명령

봇은 `.env`의 `TELEGRAM_CHAT_ID`가 보낸 메시지에만 반응한다. 다른 사람의 메시지는 응답 없이 무시한다.

| 명령 | 동작 |
| --- | --- |
| `/추가 <키워드>` | 전체 카테고리 즉시알림 키워드 추가 |
| `/추가 <카테고리> <키워드>` | 해당 카테고리만 적용 |
| `/제외 <키워드>` (`/제외 <카테고리> <키워드>`) | 제외 키워드 추가 |
| `/삭제 <키워드>` | 즉시알림·제외 목록에서 삭제 |
| `/목록` | 현재 키워드 보기 |
| `/일시정지 <시간>` | 예: `2시간`, `30분`. 그동안 발송하지 않는다. 쌓인 즉시알림은 버리고, 묶음 대상은 다음 묶음에 넣는다 |
| `/재개` | 일시정지 해제 |
| `/상태` | 소스별 마지막 성공 시각, 오류, 오늘 보낸 수 |
| `/도움말` | 명령 목록 |

텔레그램 명령은 한글 명령어를 공식 지원하지 않는다. 따라서 `/`로 시작하는 일반 텍스트를 직접 해석한다. 영문 별칭(`/add`, `/except`, `/del`, `/list`, `/pause`, `/resume`, `/status`, `/help`)도 함께 받는다.

카테고리 이름은 재테크, 알뜰폰, 카드, 핫딜, 상품권이다. 키워드는 대소문자와 공백을 무시하고 부분 일치로 비교한다.

### 6.6 유튜브 정가거부 채널

30분마다 채널 RSS를 읽는다. 영상 ID로 중복을 막는다. 6.3의 반응 기준은 적용하지 않는다. 제목으로 다음과 같이 나눈다. 위에서부터 판정한다.

1. **단종 소식:** 제목에 단종 키워드(단종, 발급중단, 발급 중단, 막차)가 있다. 🔥를 붙여 즉시 보낸다.
2. **카드 영상:** 제목에 카드 키워드(카드, 신용카드, 체크카드, 연회비, 카드 추천)가 있다. 즉시 보낸다.
3. **그 밖의 영상:** 핫딜 묶음 알림에 넣는다.

사용자의 제외 키워드는 3번에만 적용한다. 1번과 2번에는 적용하지 않는다. "단종" 영상이 "종료" 같은 제외 키워드 때문에 빠지면 안 되기 때문이다(빌더 판단). 키워드 목록은 settings.yaml에 둔다.

```
🔥 [신용카드·단종] ○○카드 단종 확정, 막차 타세요
정가거부 · 12분 전
https://www.youtube.com/watch?v=...
```

### 6.7 운영과 장애

- 소스가 3번 연속 실패하면 텔레그램으로 1번 알린다. 회복하면 회복 알림을 보낸다.
- 로그는 파일로 남기고 날짜별로 교체한다. 7일분만 보관한다.
- 처음 실행할 때는 현재 목록의 글을 "본 글"로만 기록하고 알리지 않는다. 기존 글이 한꺼번에 쏟아지는 것을 막기 위해서다.
- 90일 지난 기록은 지운다.

## 7. 배포 단계

1. **PC 테스트:** 사용자 PC에서 `python -m monitor`로 실행한다. 사용자는 BotFather로 봇을 만들고 토큰을 `.env`에 넣는다. 며칠 동안 알림 수와 품질을 보며 기준 숫자를 조정한다.
2. **Oracle 이전:** 사용자가 Oracle Cloud에 가입하고 무료 VM(Ubuntu)을 만든다. 나머지는 빌더가 안내하거나 진행한다.
   - 코드를 복사하고 venv를 만든다.
